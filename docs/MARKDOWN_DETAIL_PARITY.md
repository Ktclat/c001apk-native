Native dependencies are pinned to CommonMark Java **0.24.0** core and GFM strikethrough. Read-only task prefixes are recognized only after iterative AST validation; the upstream task extension is intentionally not used because its recursive postprocessor executes before the caller can enforce a depth bound. Table-shaped separator rows are recognized by a linear scan, with conservative fenced/indented-code exclusions, to preserve the entire source with an explicit notice. The GFM table extension is deliberately not installed: sparse tables can expand columns × rows before an AST budget is enforceable. No table cells are allocated. The [tagged POM](https://github.com/commonmark/commonmark-java/blob/commonmark-parent-0.24.0/pom.xml) targets Java 11; [tagged compatibility documentation](https://github.com/commonmark/commonmark-java/tree/commonmark-parent-0.24.0) specifies Android API 19 minimum, on a best-effort basis. This is compatible with the project's existing Java 17 target and minSdk 26, subject to the actual Android gate. The upstream README's example dependency version is stale; the verified POM and pinned coordinates establish 0.24.0. Native minSdk is unchanged by this increment. The tagged core calls Java 9 `List.of`, an Android API 30 method, so the README minimum is not sufficient evidence by itself. AGP 8.13.2 bundles D8/R8 8.13.19; the assembled minSdk-26 DEX was inspected with SDK 36 `dexdump`: all 220 CommonMark classes contain no direct `List/Set/Map.of`, `ofEntries` or `copyOf` invocation. ## Covered

- Detail-only AST-to-Compose rendering: ATX/setext headings, emphasis, strong, strikethrough, inline/fenced/indented code, quotes, ordered/bullet/nested lists, thematic rules, read-only task markers, safe explicit/reference links. No WebView or generated HTML execution.
- Conservative detection: topic `#一加13#`, `POCO_X3_GT`, an isolated ordinary list item or URL do not turn into Markdown. Comments, private messages, feed/reference previews, release notes, and the existing legacy HTML path are untouched.
- Mixed real HTML stays on the existing HTML path. It is not flattened or silently dropped by a Markdown conversion. Unsupported HTML retains the existing explicit unavailable state. Code containing HTML remains literal code.
- Existing structured article cover/title/text/image/share order, HTML inline styling, title/body font and reading presets remain. Markdown headings scale the chosen reading style; only code intentionally uses monospace. Code can scroll horizontally within a bounded segment.
- The exact `<!--break-->` marker is hidden only in formatted Markdown; raw source is unchanged, including CR/LF, comments, markup, entities and surrogate pairs.
- Persistent detail app-bar overflow source switch appears only when Markdown was detected or explicitly fell back. Raw and formatted pages/scroll positions are separate in-memory states. Raw source is selectable literal text without clickable links or image fetches. Ordinary raw text is exact `message`; structured raw source is explicitly labeled exact `message_raw_output` JSON plus separately labeled title/cover fields, not a fabricated flattened article.
- Tables, excessive structure and parse-budget overflows keep the whole source readable with an honest fallback notice. No unreviewed AST node is silently omitted.
- Markdown image syntax is a readable `图片未加载` text placeholder with alt text and literal destination, not a network request or image-URL action. Existing structured images alone continue through the unchanged strict image.coolapk.com HTTPS/DNS/redirect/decode policy.

## Bounds and ownership

All parsing, AST validation, span projection, digesting and raw pagination run in the existing detail Job on `Dispatchers.Default`; cancellation is checked before/after non-cooperative library parsing and throughout projection/pagination. Main composes only one segment with at most 4,000 UTF-16 units and 16 fragments. The existing 262,144-unit total body bound remains.

The new parser preflight admits at most 65,536 UTF-16 source units per text field, 8,192 per line, 4,096 syntax delimiters, 128 per line, 64 inline delimiters per continuous paragraph (soft newlines and CRLF cannot reset this pre-parse recursion bound), 32 bracket levels and per-line container markers and 64 leading indentation columns. AST validation admits at most 8,192 nodes and 32 levels, and projection at most 1,024 fragments, 1,024 links and 18 image placeholders. Surrogate-safe page slicing preserves span/link ranges. Structured text still shares aggregate text/span/link/page budgets with its other blocks. The continuous-paragraph guard also bounds CommonMark core’s recursive inline text-node merging before its AST is returned. These conservative bounds can cause code or literal punctuation-heavy text to use source fallback rather than formatted display.

There is no static parser/source/result cache, source logging, networking in the parser, new persistent state, account registration or credential behavior. The existing account/generation/feed/exact-body lifecycle owns all prepared results. Changed source or owner invalidates source mode in the same keyed composition; stale parsing cannot publish after cancellation. Equal-body metadata refresh preserves the current mode. Only formatted reading positions enter the existing bounded bookmark store; raw source and raw mode never enter saved state or global bookmarks.

## Deliberate parity gaps

- Raw mode defaults back to formatted after leaving and re-entering a detail; process restoration is not supported. Raw structured view shows truthful labeled API source rather than Flutter's raw text-block presentation.
- Tables use whole-source fallback; no column layout. Heading anchors, fragment scrolling, bare-URL/email autolinking, Coolapk HTML-native-link/emoji normalization, rich Markdown image loading, and preview conversion are deferred.
- Code remains segmented and has no syntax highlighting. Full-document selection, math, Mermaid, footnotes, interactive tasks, arbitrary HTML and arbitrary remote media are not implemented.
- Export is a later stage. The upstream network/media exporter is not wired. Automatic identity registration, follow-success refresh without an exact fixture, adaptive UI and external-intent parity remain separate gates.
