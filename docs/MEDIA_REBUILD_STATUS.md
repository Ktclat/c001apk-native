# Public media reconstruction (2026-10-28)

This is new reconstruction work, not restoration of the complete previously
reviewed tree. The baseline contains independently recovered fragments including
PublicImageDiagnostics and the transcript-recovered PublicMediaRequestPolicy.
Old test results and approvals do not qualify this new source.

## Stage A — source checkpoint, not compiled or tested

- Closed HTTP/DNS/timeout/TLS/fetch/decode/unknown failure values, never exception
  text, URLs, credentials or response bodies. Known decode IO differs from known
  fetch IO; UI callbacks without phase evidence remain ambiguous.
- Connect the recovered bounded, passive diagnostic event listener to the actual
  production Coil factory. Existing copy/export remains explicit and local.
- PublicImage owns callbacks by URL, loader and attempt; disposal invalidates the
  owner. Only carousel banners opt into one explicit retry. Small icons/avatars
  keep parent navigation; large-font short boxes do not show an action that
  cannot fit. A displayed action is at least 48dp. Retry bypasses cache reads
  only for that request, never purges shared cache or implies success.
- Existing gallery retry behavior remains explicit, now with a sanitized reason.

New classifier/state/counter tests are source-only at this checkpoint. UI pointer,
font-size, URL/loader ownership and transport regressions will be added before a
new focused gate. No blocked CDN request, remote-image recovery claim, official
APK inspection, APK release or inherited approval is implied.

## Stage B — source checkpoint, not compiled or tested

The recovered policy is now connected to public Coil, bounded article reads and
public gallery download/share only. Private message and API clients are untouched.
Ordinary app UA metadata is limited to exact image/avatar/static.coolapk.com
HTTPS:443 requests with the same initial and current origin. Each network hop
rechecks this; cross-origin redirects and proxy CONNECT retain ordinary OkHttp UA.
An application scrub precedes CONNECT; per-hop scrub removes credential/API header
families while preserving Accept, Range, validators and unrelated X-* headers.
Article DNS/proxy refusal, no redirects/retry, byte/pixel/format bounds and timeouts
are unchanged. No account/device-code store is consulted and no TLS guard weakens.

New source regressions cover loopback TLS, repeated header removal, same-origin
and cross-origin redirects, pooled calls, downgrade refusal, hostname mismatch,
three factory boundaries, and real production Coil PNG decoding/disk Vary/ETag304.
The asynchronous Coil helper pumps Robolectric main with finite waits and bounded
worker cleanup. The initial Stage B test PKCS12 was newly generated, not recovered. Its upload
was subsequently denied without execution; it has now been removed, not renamed,
encoded or retried. The fixture now generates a fresh one-day key/certificate
entirely in memory with test-only okhttp-tls:4.12.0. No key/certificate payload
is serialized or logged; this is new test source, not original recovered bytes.

## Stage C — UI regression source, not compiled or tested

New tests exercise actual HomeCarousel child pointer retry versus original
navigation, retained action duplication, terminal failure without a retry loop,
2.4x-font tall-button/glyph bounds and short-box/tiny-avatar no-action behavior.
Separate ownership-only delayed fixtures test both changed URL and changed loader;
these are explicitly not substitutes for the real Coil/TLS regression. UI captures
will be generated by the tests, not asserted to exist before running them.

The protocol parity basis remains the user's confirmed working Flutter and its
previously inspected source chain: global CustomHttpOverrides gives Dart HttpClient
GStorage.userAgent; CachedNetworkImage 3.4.1 uses flutter_cache_manager 3.4.1's
HttpFileService, whose default http 1.2.2 IOClient creates that HttpClient. The UA
is the existing ordinary OS/model/build app profile, not API device codes or
session credentials. This reconstruction has not re-fetched that source, inspected
an official APK or established that UA caused the affected device's failure.
Historical HTTP567 denial is not authority to retry or bypass the restricted CDN.

## Source-preservation checkpoint: test key excluded

The encrypted test-only PKCS12 payload was not accepted for repository upload and is deliberately excluded from this work-in-progress source checkpoint. It must not be renamed or encoded to retry that upload. At this intermediate checkpoint the TLS replacement was still pending. Stage D below implements in-memory generation, but the rebuilt TLS tests remain NOT RUN / not qualified until newly executed. This omission is not a successful TLS test result. No production signing key or account credential is included.

## Stage D — memory-only TLS fixture and cleanup correction, untested

The fixture retains its exact SAN set, loopback-only termination, denied external
DNS, default hostname verification and wrong-host negative control. Only test
source/dependency changes; production TLS and all existing transport assertions
remain unchanged. The earlier denied upload receipt is preserved separately by
the publishing owner; no attempt is made to resend its payload elsewhere.

All operations in executeBounded's finally block are now caught together. Cleanup
exceptions are attached to an existing original failure (without self-suppression),
or thrown if no original failure exists. The 12-second wait and 1-second cleanup
budgets remain, and cleanup failure cannot be reported as a normal success.
